# 成品 vs 设计稿 差异清单（v0.3.0 实机截图）

> 比对对象：`Clipboard_Screenshot.png`（2368×1804 物理像素）
> 环境：4K 屏 200% 缩放 → DPR 2 → **逻辑尺寸 1184×902**
> 设计基准：1440×900 @1x
> 本文所有数值均为**逻辑像素**（已除以 2），可直接用于实现，**不要再乘缩放比**。

---

## 0. 一句话结论

**颜色系统基本还原了，问题集中在"尺寸没有固定"**：控件高度、内边距、行高都是让内容自然撑出来的（sizeHint / QSS padding 推导），字号或字体一换就整体缩一号。设计稿里那些 34 / 28 / 38 / 36 都是**写死的高度**，必须显式设成 `setFixedHeight()` 或 QSS 的 `min-height + max-height`。

三类根因：

| # | 根因 | 表现 |
| --- | --- | --- |
| R1 | 控件高度用默认推导，没锁死 | 导航行、筛选胶囊、空态按钮都比规范矮 6–12px，整屏显得"紧、小一号" |
| R2 | 为塞进 1184 宽窗口，把内容内边距从 32 压到 ~12 | 标题几乎贴住侧栏，右侧也没有安全边；正确做法是**卡宽自适应，padding 不动** |
| R3 | 两个组件用了临时实现，没走组件规范 | 视图切换被拆成两个独立按钮；"更多"用了文本省略号 |

## 1. 必须改（直接影响是否"像设计稿"）

| # | 位置 | 设计稿 | 实测 | 怎么改 |

| 2 | 侧栏导航行高 | **34**（行距 36） | ≈**22–24**（行距 ≈29） | 行 `setFixedHeight(34)`；列表 `spacing(2)` |

## 3. 空状态：规范缺细则，按下面补

设计稿只写了"空状态需居中卡片"，没给数值，实现自由发挥后跑偏了。建议定成：

| 项 | 建议值 | 实测偏差 |
| --- | --- | --- |
| 卡片 | 440×200，圆角 **12**，底 `#0E121A`，描边 1px `#FFF 6%` | 438×196 ✓ 尺寸对，**圆角 16 偏大** |
| 卡片内边距 | **18**（不是 30） | ≈30，卡片显得空 |
| 图标 | 40×40，**文件夹 + 加号**，描边 1.8，色 `#3D8BFF` | 用了四宫格（= 游戏库），语义是"添加目录"不是"浏览库"；线宽也偏粗（≈3） |
| 标题 | 15 / 700 / `#F2F5FA` | ✓ 基本对 |
| 描述 | 11.5 / 400 / `#5F6A80`，与标题间距 6 | ✓ |
| 主按钮 | **高 38，圆角 9**，整宽铺满（卡内 padding 内），带 11px 播放/加号图标，渐变同主按钮 | 高度仅 ≈22–28、**圆角是胶囊（≈高度一半）**、未整宽对齐规范——形状脱离了按钮系统 |

> 关键：项目里按钮只有两种圆角（主/次 9、小控件 8、图标按钮 7），**没有胶囊按钮**。胶囊只属于筛选 chip 和状态 pill。

## 4. 布局自适应规则（补齐设计稿缺口）

设计稿只画了 1440 宽，1184 宽下的行为没定义，所以实现拿 padding 去凑空间。正确规则：

```
侧栏         固定 236
内容内边距    固定 32（上下 24）
可用宽 C = 窗口宽 − 236 − 64        // 1440 → 1140；1184 → 884
卡宽 = (C − 16×(列数−1)) / 列数      // 列数默认 3
封面高 = 卡宽 × 9 / 16
```

| 窗口宽 | 可用宽 C | 3 列卡宽 / 封面 | 结论 |
| --- | --- | --- | --- |
| 1440 | 1140 | 369 / 207 | 与设计稿一致 |
| 1280 | 980 | 316 / 178 | 可 |
| 1184（当前） | 884 | 284 / 160 | 可，**不需要降到 2 列** |
| < 1080 | < 780 | — | 切 2 列：(C−16)/2 |

同时也建议：**默认窗口 1440×900**（4K@200% 下逻辑屏 1920×1080，完全放得下）。当前 1184×902 的窗口会让设计稿的留白整个消失，观感差异有一半来自这里。
